# 다국어 경로 규칙 (`/[lang]/...`)

> 결정 2026-10-24 (사용자): 나중에 일본 외 시장으로 넓힐 수 있게 모든 사용자 화면을 언어 구간 아래에 둔다.

## 경로
| 값 | 용도 | `<html lang>` |
|---|---|---|
| `jp` | 일본 대상 서비스 (기본) | `ja` |
| `ko` | 개발·확인용 한국어 | `ko` |

- 환자 화면: `/[lang]/...` 예) `/jp/intake`, `/ko/quote/{id}`
- 의원 콘솔도 같은 규칙: `/[lang]/clinic/...` 예) `/ko/clinic`, `/jp/clinic/consult/{id}`
- 언어 구간이 없는 경로(`/`, `/intake` 등)는 `/jp/...`로 리다이렉트한다.
- 언어 구간 밖에 남는 것: `/api/*`, `/dev/*`(개발용), 정적 파일.
- 경로 값(`jp`)과 HTML 언어 코드(`ja`)는 다르다 — 사용자 결정. 변환은 `lib/i18n.ts` 한 곳에서만 한다.
- 새 언어 추가 = `LANGS`에 값 하나와 사전 파일 추가로 끝나야 한다.

## 구현 (H1이 기반, 각 레인이 자기 화면)
```
apps/web/
├── proxy.ts                  # 언어 없는 경로 → /jp 리다이렉트 (Next 16: middleware → proxy)
├── lib/i18n.ts               # LANGS, DEFAULT_LANG, isLang(), htmlLang(), getDict(lang), href(lang, path)
├── dictionaries/
│   ├── jp/  common.ts  h2.ts  h3.ts  h4.ts
│   └── ko/  common.ts  h2.ts  h3.ts  h4.ts
└── app/
    ├── [lang]/
    │   ├── layout.tsx        # lang 검증(notFound) + <html lang>
    │   ├── (patient)/...     # H2·H3·H4 화면
    │   └── clinic/...        # H3·H4 의원 화면
    ├── api/
    └── dev/
```
- 사전은 **레인별 파일**로 나눠 충돌을 막는다. `common.ts`는 H1 소유(공통 틀·버튼 등), `h2.ts`~`h4.ts`는 각 레인 소유.
- `ko/*.ts`는 `jp/*.ts`와 같은 타입이어야 한다(`satisfies typeof jp`) — 키 누락을 빌드에서 잡는다.
- 화면 문구는 하드코딩하지 않고 사전에서 읽는다. 의원 콘솔의 `jp` 문구는 아직 번역이 없으면 한국어를 그대로 넣어도 된다(키만 맞추면 됨).
- 내부 링크·`redirect()`·`revalidatePath()`·화상 `returnUrl`은 반드시 `href(lang, path)`로 만든다. `"/intake"` 같은 문자열 하드코딩 금지.
- 사용자 데이터(시술명·의원명 등 DB 값)는 이번 범위가 아니다. 지금 있는 `name_ja` 같은 컬럼을 그대로 쓴다.
