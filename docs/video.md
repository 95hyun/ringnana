# 1:1 화상 진료 (video)

> 소유: **화상통화 담당(`apps/video`)**. 플랫폼과 맞닿는 부분은 [video-integration.md](video-integration.md) 계약을 따른다.
> 상태: 초안 (2026-10-24). 플랫폼 쪽 확인이 필요한 항목은 [requests.md](requests.md)에 남겼다.
> 이 문서 하나에 1:1 화상 진료의 통화·얼굴 촬영·실시간 통역을 모두 적는다.

## 1. 무엇을 왜
- 의사·환자 **1:1** 화상통화 위에 두 기능을 얹는다.
  - **얼굴 3방향 가이드 촬영:** 의사가 [얼굴 촬영 요청]을 누르면 환자가 안내(문구 + 화살표 + 각도 진행바)대로 정면 → 좌측 → 우측으로 얼굴을 돌리고, 기준 각도에 닿으면 **자동 촬영**된다. 3장을 미리보기로 확인·재촬영한 뒤 제출하면, 사진이 의사 화면에 원본 화질로 도착한다.
  - **실시간 AI 통역:** 의사의 한국어를 일본어로, 환자의 일본어를 한국어로 **양방향** 통역한다. 듣는 쪽 화면에 번역 자막을 띄우고, 같은 문장을 듣는 쪽 언어 음성으로 읽어 준다.
- 통화 밖 기능 하나를 더 맡는다: **소견 일본어 번역**(§5.7). 의사가 의원 콘솔에서 저장한 소견을 화상 앱 서버가 일본어로 번역해 진료 기록에 저장한다.
- 촬영: 화상통화 영상은 압축돼 색소 판독에 화질이 부족하고, 환자가 따로 찍어 보낸 사진은 각도·조명이 제각각이라 재촬영이 잦다([product/plan.md](product/plan.md) §6 사진 표준화). 그래서 대화는 통화로 하고, **진단용 사진은 환자 단말 카메라 원본 화질로 따로 찍는다.** 통화는 끊지 않는다. 플랫폼 `/photos`는 셀카 1장 + AI 목표 이미지 화면으로 바뀌었으므로, **정면·좌·우 표준 사진은 이 기능이 찍는다**(scope P0). 통화 중 찍은 정면 사진은 귀국 후 경과 비교의 기준 사진으로도 쓴다(§5.6).
- 통역: 기획안의 "설명 격차"(통역 경유로 부작용·회복 이해 부족, [product/plan.md](product/plan.md))를 데모에서 보여 주는 장면이다. 데모는 1:1 통화라 사람 통역사 대신 AI 통역을 쓴다.
- "얼굴인식"은 **얼굴 검출 + 고개 각도 추정**을 뜻한다. 신원 확인이 아니며, 얼굴 특징값을 만들거나 저장하지 않는다.
- 의료 판단은 하지 않는다. 자동 로직은 얼굴 검출·고개 각도·사진 품질 판단, 받아쓰기·번역·읽어 주기까지만 한다. 소견·견적은 의원 콘솔(H3)에서 의사가 작성한다. 번역은 틀릴 수 있으므로 **원문을 항상 함께 보여 주고 AI 번역임을 표시한다.**
- 시간이 부족할 때 지키는 순서: **촬영 흐름 > 화상통화 > 통역.** 화상통화가 안 되더라도 촬영 → 업로드 → 의사 화면 표시는 단독으로 돌아야 한다(§7 테스트 진입).

## 2. 범위

| 포함 (데모) | 하지 않음 |
|---|---|
| 의사·환자 **1:1** 화상통화(영상 + 음성) (`role=interpreter`는 계약에만 두고 데모 미지원) | 3자 통화(사람 통역사), 화면 공유, 통화 녹화 |

| 번역 자막 + 원문 + 듣는 쪽 언어 음성(TTS), 통역·음성 켜기/끄기 | 통역 기록 저장·진료 기록 연동 |

시간이 남으면 넣는 것: 입장 전 카메라·마이크 점검 화면 `/check`(§7, 플랫폼 H3 제안 수락).

## 3. 데모 흐름 (노트북 2대)
1. 의원 콘솔·환자 화면에서 화상 진료에 입장한다. 진입 주소는 [video-integration.md](video-integration.md) §1의 `/room/{sessionId}?role=...`이고, 새 탭으로 연다.
2. 1:1 통화가 연결되고, 통역이 켜진 상태로 문진 대화를 한다. 서로의 말이 상대 언어 자막·음성으로 나온다.
3. 의사가 [얼굴 촬영 요청]을 누른다. 환자 화면은 **내 영상(가이드 포함)을 크게, 의사 영상을 작게** 바꾸고 동의 체크를 띄운다.
4. 환자가 동의하고 안내대로 정면·좌측·우측을 돌리면 자동 촬영된다. 의사 화면은 "촬영 중 1/3…"으로 진행만 표시한다.
5. 환자는 미리보기에서 3장을 확인하고, 필요하면 그 방향만 다시 찍은 뒤 [提出する]를 누른다. 3장이 한꺼번에 올라가고 의사 화면에 표시된다.
6. 제출이 끝나면 환자 화면은 원래 배치로 돌아가고 "医師が写真を確認しています"를 표시한다. 사진이 마음에 들지 않으면 의사가 다시 요청한다. 새 촬영 회차로 동의부터 다시 시작한다.
7. 의사가 [통화 종료]를 누르면 의사와 환자가 함께 각자의 `returnUrl`로 돌아간다. 의원 콘솔에서 통화 중 사진을 보며 소견·견적을 쓰고, 저장하면 콘솔이 화상 앱에 소견 번역을 요청한다(§5.7). 환자 견적 화면에는 일본어 번역이 「自動翻訳」 표시와 함께 나온다.

## 4. 통화 공통 화면 규칙
- 카메라·마이크는 한 번만 요청한다(1920×1080 우선, 안 되면 1280×720, 그것도 안 되면 카메라가 주는 해상도). 같은 영상을 통화와 촬영에, 같은 마이크를 통화와 통역에 쓴다.
- 내 영상은 거울처럼 좌우 반전해서 보여 준다. **저장 사진은 반전하지 않은 원본**이다.
- 기본 배치: 상대 영상 크게, 내 영상 작게.
- 언어: 의사 화면은 한국어 고정. 환자 화면은 **일본어 기본 + 한국어 전환**이다(심사위원에게 한국어 화면도 보여 주기 위해). PC Chrome 가로 화면 기준이다.
  - 환자 화면 오른쪽 위에 `日本語 / 한국어` 전환 버튼을 둔다. 처음 언어는 `lang`(기본 `ja`)이고, 고른 언어는 **그 진료방(sessionId) 안에서만** 새로고침해도 유지한다. 새 진료방은 다시 `lang`으로 시작한다(리허설 때 바꾼 언어가 실제 시연에 남지 않게).
  - 환자 화면 문구(안내·버튼·오류·동의·상태)는 ja/ko 두 문구 파일에서 가져오고, 화면 코드에 직접 쓰지 않는다. 의사 화면은 한국어로 직접 써도 된다.
  - 이 문서의 환자 문구는 일본어판이다. 한국어판은 같은 뜻으로 쓴다.
  - 전환 버튼과 `lang`은 화면 문구만 바꾼다. **통역 언어는 역할로 고정한다: 의사 = 한국어, 환자 = 일본어.** 환자가 한국어 경로(`lang=ko`)로 들어오거나 화면을 한국어로 바꿔도 환자의 말하기·듣기는 일본어다(서비스 대상이 일본인 환자이고, 데모의 환자 역할은 일본어로 말한다).
- 상대 입장 표시: 의사 "환자 대기 중 / 환자 연결됨", 환자 "医師をお待ちください / 医師と接続しました".
- 의사가 연결을 제안하고 환자가 응답한다(역할 고정 — 양쪽이 동시에 제안하는 충돌을 피한다). 의사는 **내 영상 준비 + 환자 입장**이 모두 충족될 때만 제안한다. 새로고침·재입장 때는 의사가 다시 제안해 재연결한다. 상대가 나가면 연결을 정리하고 대기 상태로 돌아간다. 새로고침 없이 네트워크만 끊긴 경우의 자동 복구는 범위 밖이다(새로고침으로 복구).
- **같은 역할의 창이 하나 더 열리면 새 창이 이긴다.** 먼저 열린 창은 카메라·마이크·연결을 모두 닫고 "다른 창에서 입장했습니다" / 「別のウィンドウで入室しました」를 띄운 채 멈춘다. 상대는 새 창하고만 연결한다(콘솔이 [화상 진료 시작]마다 새 탭을 열기 때문).
- **통화 종료:** 양쪽 화면에 [통화 종료] / [通話を終了] 버튼을 둔다.
  - 의사가 누르면 환자에게 종료를 알리고, 의사는 자기 `returnUrl`로 이동한다. 환자는 알림을 받으면 자기 `returnUrl`로 이동한다. 단, 환자가 사진을 **제출하는 중**이면 제출이 끝날 때까지(성공이든 실패든) 기다렸다가 이동한다. 아직 제출하지 않은 촬영분은 버린다.
  - 환자가 누르면 환자만 자기 `returnUrl`로 이동한다. 의사 화면은 "환자 대기 중"으로 돌아간다.
  - `returnUrl`이 없으면(테스트 진입 등) 이동하지 않고 "통화가 종료되었습니다" / 「通話が終了しました」를 표시한다.
- 카메라 오류:

| 상황 | 의사 (한국어) | 환자 (일본어) |
|---|---|---|
| 권한 거부 | 카메라·마이크 권한이 필요합니다. 주소창의 카메라 아이콘에서 허용해 주세요 + [다시 시도] | カメラとマイクの許可が必要です。アドレスバーのカメラアイコンから許可してください + [もう一度試す] |
| 카메라 없음 | 카메라를 찾을 수 없습니다 | カメラが見つかりません |
| 다른 프로그램이 사용 중 | 다른 프로그램에서 카메라를 사용 중입니다. 종료 후 다시 시도해 주세요 + [다시 시도] | 他のアプリでカメラが使用中です。終了してからもう一度お試しください + [もう一度試す] |

## 5. 얼굴 3방향 가이드 촬영

### 5.1 의사 화면
- [얼굴 촬영 요청]은 환자가 방에 있을 때만 누를 수 있다.
- 요청하면 **새 촬영 회차(batch)**가 생긴다. 이전 회차 사진은 화면에서 내리고 "촬영 중 0/3"을 표시한다. 환자가 한 장 찍을 때마다 진행 수만 늘린다(사진은 아직 오지 않음).
- 환자가 제출하면 정면·좌측·우측 3장을 한꺼번에 표시한다.
- 촬영 도중 다시 요청해도 새 회차로 동의부터 시작한다. 이전 회차는 제출 전이면 아무것도 남지 않고, 제출된 회차는 지우지 않고 남겨 둔다.
- **[촬영 취소]는 의사만** 쓸 수 있다. 촬영 요청 후 제출 전까지 보인다. 누르면 환자 화면은 찍은 사진을 버리고 통화 배치로 돌아가며, 의사 화면은 최신 제출 회차 사진(없으면 빈 자리)으로 돌아간다. 환자는 취소할 수 없다(동의하지 않으면 시작하지 않고 기다리며, 의사가 취소한다).
- 촬영 중 환자가 나가면(창 닫기·새로고침) 의사 화면도 진행 표시를 지우고 최신 제출 회차로 돌아간다.

### 5.2 동의 체크
- 촬영 전에 반드시 받는다: 「顔写真を診療目的で収集・利用することに同意します。写真は担当の医師のみが確認します。」 체크해야 [撮影を始める]가 켜진다.
- 체크한 시각을 동의 시각으로 기록하고, 제출 때 사진과 함께 저장한다.

### 5.3 가이드 촬영 (환자 브라우저에서만 분석)
- 얼굴 검출과 고개 각도 추정은 MediaPipe Face Landmarker(`@mediapipe/tasks-vision`, Apache 2.0)로 한다. wasm과 모델 파일은 앱 안에 두고, CDN은 쓰지 않는다(얼굴 분석은 인터넷 없이도 돈다). 상업 사용이 제한된 모델(InsightFace 모델, dlib 68점 모델)은 쓰지 않는다.
- 순서는 정면 → 좌측 → 우측으로 고정한다. 화면 위쪽에 단계 표시 ① 正面 ② 左 ③ 右를 두고, 끝난 단계에 ✔를 붙인다.
- **좌우는 환자 본인 기준**이고, 화살표(애니메이션)는 거울 모드 화면에서 고개를 돌리는 방향과 맞춘다. 얼굴 분석 결과에서 어느 쪽이 왼쪽인지는 **실제 웹캠으로 확인해 맞춘다.** 추측한 부호로 끝내지 않는다.
- **각도·위치 표기 약속:** `yaw`는 도 단위, **양수 = 환자가 자기 왼쪽으로 돌림**. `pitch`는 양수 = 위를 봄. 얼굴 크기·위치는 반전하지 않은 원본 프레임 기준이다(크기 = 얼굴 상자 너비 ÷ 프레임 너비, 위치 = 얼굴 상자 중심 (x, y)를 0~1로).
- 진행바: 측면 단계는 목표 각도까지 얼마나 돌렸는지, 정면 단계는 정면에 얼마나 가까운지 보여 준다.

| 단계 | 안내 (환자, 일본어) | 화살표 | 촬영 조건 (기본값, 조정 가능) |
|---|---|---|---|
| 정면 `front` | 正面を向いてください | 없음 (가운데 원형 가이드) | \|yaw\| ≤ 5°, \|pitch\| ≤ 15° (PC 웹캠 기준으로 넓힘) |
| 좌측 `left` | 顔を左に向けてください | ◀ | 본인 왼쪽으로 yaw 35°~55°, \|pitch\| ≤ 15° |
| 우측 `right` | 顔を右に向けてください | ▶ | 본인 오른쪽으로 yaw 35°~55°, \|pitch\| ≤ 15° |

| 상태 | 자동 촬영 | 표시 (환자, 일본어) |
|---|---|---|
| 얼굴 없음 | 막음 | 顔を枠の中に合わせてください (가이드 회색) |
| 2명 이상 | 막음 | お一人だけ映るようにしてください |
| 너무 멂 / 가까움 | 막음 | もう少し近づいてください / 少し離れてください |
| 가운데에서 벗어남 | 막음 | 顔を中央に合わせてください |
| 각도 부족 | 막음 | 화살표 강조 + 진행바 증가 |
| 각도 초과 | 막음 | 少しだけ戻してください |
| 화면이 어두움 | **막지 않음** | もう少し明るい場所に移動してください |
| 막는 조건 모두 통과 | 유지 타이머 진행 | 가이드 초록색 |
| 촬영 완료 | — | ✔ 표시 후 다음 단계로 자동 전환 |

- 막는 조건을 모두 통과한 상태가 약 1초 끊기지 않고 유지되면 촬영한다. 하나라도 벗어나면 타이머를 0으로 되돌린다. 밝기는 안내만 한다(행사장이 어두우면 시연이 멈출 수 있어서).
- 한 단계에서 15초 동안 자동 촬영이 안 되면 [手動で撮影] 버튼을 띄운다. 수동 촬영은 **조건과 상관없이** 현재 프레임을 찍고 `capture_mode = manual`로 저장한다. 얼굴이 없으면 `yaw`·`pitch`는 비운다.
- 촬영 순간: 카메라 원본 해상도 프레임을 JPEG(품질 약 0.92)로 만들고, 화면 번쩍임과 셔터 효과음을 낸 뒤 ✔를 표시하고 다음 단계로 넘어간다. 찍을 때마다 의사에게 진행 알림을 보낸다(사진은 보내지 않음).
- 각도·시간·크기·위치·밝기 기준값은 설정 파일 하나에 모아 현장에서 조정할 수 있게 한다(§10).

### 5.4 미리보기·재촬영·제출
- 3장을 모두 찍으면 썸네일 3장, 사진마다 [撮り直す], 그리고 [提出する]를 보여 준다.
- [撮り直す]를 누르면 **그 방향 단계만** 다시 찍고 미리보기로 돌아온다.
- [提出する]를 누르면 3장을 **한꺼번에** 올린다. 올리는 동안 버튼을 끄고 「送信中…」을 표시한다.
- **사진 3장이 모두 저장된 뒤에만 기록이 생긴다.** 중간에 그만두거나 실패하면 의원 콘솔에 아무것도 나타나지 않는다(미완성 기록이 남지 않고 재촬영이 깔끔하다).
- 실패하면 찍은 사진을 화면에 그대로 두고 「送信に失敗しました。インターネット接続を確認してください」와 [もう一度提出]를 보여 준다. 다시 제출해도 같은 회차로 기록이 2개 생기면 안 된다.
- 제출한 뒤에는 환자가 그 회차의 사진을 바꿀 수 없다. 다시 찍으려면 의사가 새로 요청한다.

### 5.5 새로고침
- 화면끼리 주고받는 실시간 알림은 지나간 것을 다시 받을 수 없다. 그래서 화면 상태는 **항상 서버에서 다시 불러온 데이터 기준**으로 맞춘다.
- 의사 화면은 처음 열릴 때 그 진료의 최신 제출 회차 사진을 다시 불러온다.
- 환자가 제출 전에 새로고침하면 찍은 사진은 버리고 이어 찍지 않는다. 의사가 다시 요청한다.

### 5.6 플랫폼에 저장하는 방식 → [video-integration.md](video-integration.md) §4
- 저장 위치는 플랫폼과 같은 Supabase의 `photos` 테이블과 비공개 사진 버킷이다.
- 진료는 `consultations.video_session_id = sessionId`로 찾는다.
- 각 행에는 `source = call`, `consultation_id`, `patient_id`, 진료의 `intake_id`(있으면), `capture_batch_id`, `capture_mode`, `yaw`, `pitch`, `quality_ok`(auto = true, manual = false), `consented_at`을 넣는다. `intake_id`를 넣는 이유는 귀국 후 경과 비교에서 이 정면 사진을 기준으로 쓰게 하기 위해서다(기준 사진 선택 변경은 플랫폼 H4에 요청).
- 한 회차의 사진 3행은 **한 번에** 넣는다(3장이 다 들어가기 전에 일부가 보이면 안 된다). 같은 회차를 다시 제출했을 때 이미 저장돼 있으면 아무것도 바꾸지 않고 성공으로 응답한다. 아직 없으면 버킷의 같은 경로에 덮어써 이전 실패의 잔여 파일을 정리한 뒤 저장한다.
- 필요한 컬럼 추가와 버킷 이름은 H1에 요청했다([requests.md](requests.md)).

### 5.7 소견 일본어 번역 (화상 앱 서버가 제공)
- 플랫폼은 소견 번역을 만들지 않기로 했다(사용자 결정, 화상 담당 몫). 화상 앱 서버가 번역 기능을 제공하고, 호출과 표시는 플랫폼에 요청한다([video-integration.md](video-integration.md) §6, [requests.md](requests.md)).
- 대상은 `consultations.notes`(의사 소견, 한국어) 한 칸이다. 권장 관리는 플랫폼에 칸이 없어 번역하지 않는다.
- **호출:** 의사가 의원 콘솔에서 소견을 저장한 직후, **콘솔 화면(의사 브라우저)**이 화상 앱의 `POST /api/opinion/translate { consultationId }`를 부른다. 의사 브라우저는 통화 때 화상 앱의 개발용 인증서를 이미 허용했으므로 연결된다. 서버끼리 부르지 않는다(개발용 인증서 때문에 시연 직전 실패 위험).
- **처리:** 화상 앱 서버가 그 진료의 현재 `notes`를 읽어 `notes_translation_status = pending`으로 바꾼 뒤 번역한다. 성공하면 번역문(`notes_ja`), **번역한 원문**(`notes_ja_source`), `done`을 저장한다. 실패·시간 초과·거절이면 `failed`로 바꾼다. 소견이 비어 있으면 번역하지 않고 409.
- **고치기 전 번역 노출 금지:** 환자 화면은 `notes_translation_status = done`이고 `notes_ja_source`가 현재 `notes`와 **같을 때만** 번역을 보여 준다. 다르면(의사가 고친 뒤 아직 번역 전) 원문과 「翻訳を準備中です」를 보여 준다. 그래서 플랫폼의 소견 저장 코드는 바꾸지 않아도 된다.
- **번역 중 소견이 다시 저장되면:** 저장 직전에 원문이 바뀌었는지 확인하고, 바뀌었으면 결과를 버린다(다음 호출이 새 원문을 번역한다).
- 번역: Claude API(`claude-sonnet-5-5`, effort `medium`). 한국 피부과 의사의 소견을 일본인 환자에게 전하는 정중한 です・ます체로, 의미를 더하거나 빼지 않고 번역문만 낸다. 시간 초과 30초. 키는 서버 전용.
- 환자 견적 화면(플랫폼 H4, 요청): 일본어 화면이면 번역본 + 「自動翻訳」 표시 + [原文を見る](한국어 원문 펼치기). 한국어 화면이면 원문 그대로.
- 의원 콘솔(플랫폼 H3, 요청): 번역 상태를 `번역 중`/`번역 완료`/`번역 실패`로 보이고, 번역이 최신이 아니면(실패, 준비 중에서 멈춤, 원문과 다름) [다시 번역]을 보여 준다. [다시 번역]은 같은 기능을 다시 부른다.

## 6. 실시간 AI 통역 (A안: 브라우저 내장 기능 + 번역 API)

```
말하는 쪽 브라우저                          video 서버                 듣는 쪽 브라우저
Web Speech API(STT, 내 언어) ─확정 문장→ POST /api/translate ─번역→ Realtime 방송 ─→ 자막 표시 + speechSynthesis(TTS, 내 언어)
        └─ 내 화면: 원문 + 번역 (확인용)
```

### 6.1 방식
- **STT:** Chrome Web Speech API(`SpeechRecognition`). 언어는 역할로 고정(의사 `ko-KR`, 환자 `ja-JP`, §4). 연속 인식 + 중간 결과를 켜고, **확정 결과(final)만 번역한다.** 중간 결과는 내 화면에만 회색으로 보인다.
- **번역:** video 앱 서버 경로 `POST /api/translate`. 기본은 Claude API(`claude-haiku-5-5`, 속도 우선)이고, 경로 안에서만 바꾸면 다른 번역 API로 교체할 수 있다. API 키는 서버에만 둔다.
- **전달:** 통화 신호와 같은 Supabase Realtime 채널 `video:{sessionId}`로 방송한다(§7). WebRTC 데이터 채널은 쓰지 않는다.
- **TTS:** 듣는 쪽 브라우저 `speechSynthesis`. 언어는 역할로 고정(환자 `ja-JP`, 의사 `ko-KR`). 해당 언어 음성이 없으면 자막만 보여 준다.

### 6.2 번역 규칙 (서버 프롬프트)
- 피부과 화상 진료 대화라는 맥락을 준다. 들은 말만 옮기고, 설명·의견을 덧붙이지 않는다. 일본어는 정중한 です・ます체로 옮긴다.
- 숫자·단위·횟수·기간·약 이름·시술 이름은 그대로 정확히 옮긴다. 의학 용어는 일본에서 일반적으로 쓰는 표현을 쓴다.
- 출력은 번역문 한 줄만. 의료 용어 대역표는 설정 파일 하나에 모아 현장에서 고칠 수 있게 한다.
- 실패하거나 3초 안에 응답이 없으면 듣는 쪽에 원문만 보내고 "翻訳できませんでした" / "번역하지 못했습니다"를 붙인다.
- 문장 길이 제한(약 500자)을 두고, 그 이상은 잘라서 보낸다.

### 6.3 자막
- 상대 영상 아래에 자막 영역을 둔다. 위: 번역문(크게), 아래: 원문(작게, 회색). 오른쪽 위에 `AI翻訳` / `AI 번역` 표시.
- 최근 3문장까지 보이고, 오래된 문장부터 위로 밀려 사라진다.
- 내가 한 말도 내 화면 아래에 원문 + 번역으로 보여 준다. 말한 사람이 번역이 맞는지 바로 확인하게 하려는 것이다. 번역 응답을 기다리는 동안에는 원문만 먼저 띄운다.
- 환자 촬영 중(§5)에도 자막은 계속 보인다. 번역문·원문은 화면 언어 전환과 상관없이 그대로 보여 준다.

### 6.4 음성 읽기
- 번역 문장이 도착하는 순서대로 하나씩 읽는다(대기열). 읽는 동안 상대 원음 볼륨을 약 20%로 낮췄다가 끝나면 되돌린다.
- **읽는 동안에는 내 STT 결과를 버린다.** 스피커로 나온 번역 음성을 내 마이크가 다시 받아 번역이 되돌아가는 것을 막기 위해서다.

### 6.5 켜기/끄기·상태 표시
- 버튼 두 개: [통역] (STT·번역 전체), [음성] (TTS만). 기본은 둘 다 켬. 의사 화면은 한국어, 환자 화면은 일본어(`通訳` / `音声`)로 표시한다.
- 마이크 음소거 중에는 STT도 멈춘다.

| 상태 | 의사 (한국어) | 환자 (일본어) |
|---|---|---|
| 듣는 중 | 듣는 중… | 聞き取り中… |
| 번역 중 | 번역 중… | 翻訳中… |
| 지원 안 되는 브라우저 | 이 브라우저는 통역을 지원하지 않습니다 (Chrome 사용) | このブラウザは通訳に対応していません（Chromeをご利用ください） |

## 7. video 앱 내부 구조 (플랫폼과 무관)
- 연결 정보 교환과 화면 간 알림에는 Supabase Realtime(Broadcast + Presence)을 쓴다. 외부 연결 중개 서비스(PeerJS 등)는 장애가 나면 시연이 좌우되므로 쓰지 않는다. 채널은 진료당 하나이고, 이름 `video:{sessionId}`로 플랫폼 채널과 겹치지 않게 한다. 연결은 직접 연결(P2P)이 기본이다. 공개 STUN에 더해, **중계 서버(TURN) 설정이 있으면 함께 쓴다** — 행사장 네트워크가 기기 간 직접 연결을 막을 때만 중계를 탄다. 설정이 없으면 STUN만으로 동작한다. 중계 서버 목록은 화상 앱 서버(`GET /api/ice`)가 내려준다(특정 중계 서비스에 묶이지 않게 주소·사용자명·비밀번호를 환경변수로 받는다).
- Presence: 키는 역할(`doctor` / `patient`), 값은 `{ role, tabId, joinedAt }`. 같은 역할에 여러 창이 있으면 `joinedAt`이 가장 늦은 창만 유효하다(§4).
- 이벤트 (Broadcast):

| 이벤트 | 보내는 쪽 | 내용 | 받는 쪽 동작 |
|---|---|---|---|
| `signal` | 양쪽 | `{ from: 'doctor'\|'patient', kind: 'offer'\|'answer'\|'ice', data }` | 화상통화 연결 정보 처리 |
| `capture:request` | 의사 | `{ batchId }` | 환자: 현재 회차를 이 ID로 바꾸고 동의 체크부터 시작 |
| `capture:progress` | 환자 | `{ batchId, angle }` | 의사: 진행 수 갱신 (재촬영해도 방향 기준으로 셈) |
| `capture:done` | 환자 | `{ batchId }` | 의사: 제출 완료 — 최신 데이터 다시 불러와 사진 3장 표시 |
| `capture:cancel` | 의사 | `{ batchId }` | 환자: 촬영분 버리고 통화 배치로 복귀 |
| `call:end` | 의사 | `{}` | 환자: 제출 중이면 끝난 뒤, 아니면 바로 자기 `returnUrl`로 이동 |
| `interp:caption` | 말하는 쪽 | `{ id, speaker, srcLang, srcText, dstLang, dstText, failed }` | 자막 표시 + 음성 읽기 |

- 촬영 회차 ID는 의사가 요청할 때 만들어 `capture:request`에 싣고, 재제출 때도 같은 ID를 써서 중복 기록을 막는다. 모든 촬영 이벤트와 제출에 `batchId`가 붙고, 각 화면은 **현재 회차와 다른 `batchId`의 이벤트를 무시**한다(재요청 뒤 늦게 도착한 이전 사진이 섞이지 않게).
- 데이터 변경 알림은 DB 변경 구독이 아니라 위 이벤트로 보낸다(브라우저가 테이블을 직접 읽지 않기 때문).
- 통역 `id`는 문장마다 새 UUID이고, 같은 `id`는 한 번만 표시·재생한다. Chrome 연속 인식은 일정 시간 뒤 스스로 끝나므로(`onend`), 통역이 켜져 있으면 바로 다시 시작한다.
- 사진 업로드·조회와 번역은 video 앱 서버 경로에서만 한다. 제출은 3장(`front`·`left`·`right`)과 각 사진 정보(`angle`, `captureMode`, `yaw`, `pitch`), `batchId`, 동의 시각을 multipart 한 요청으로 받는다(요청 크기 제한이 작은 서버 함수 호출은 쓰지 않는다). 방향마다 사진과 정보가 정확히 하나씩 없거나 값이 허용 범위를 벗어나면 400으로 거부한다. 브라우저에는 사진 임시 주소(signed URL, 10분)만 준다.
- 촬영 화면은 통화 화면과 분리된 **부품**으로 만든다. 입력: 이미 켠 카메라 영상(넘기지 않으면 직접 켜고, 끝날 때는 직접 켠 카메라만 끈다), 언어, 촬영 회차 ID. 동의 체크는 부품 안에서 받는다. 출력: 한 장 찍힐 때마다 방향 알림, 제출 완료 알림. 촬영 판단 로직은 화면·카메라와 분리된 순수 로직으로 둔다.
- 통역 문장은 저장하지 않는다. 화면을 닫으면 사라진다.
- 소견 번역 기능(`POST /api/opinion/translate`)은 다른 출처(의원 콘솔)에서 브라우저로 부르므로, 허용할 출처를 환경변수로 받아 CORS를 연다.
- (시간이 남으면) 점검 화면 `/check?lang={ja|ko}&returnUrl=…`: 카메라 미리보기, 마이크 입력 레벨, 스피커 테스트음, 권한 거부 시 해결 안내. 여기서 권한을 허용해 두면 같은 출처라 입장 때 다시 묻지 않는다. 결과는 플랫폼에 보내지 않는다.
- 개발·비상용 진입: `?role=patient&test=1`이면 환자 화면에 [撮影テスト] 버튼이 나타나고, 통화 없이 환자 화면이 직접 새 회차를 만들어 동의 → 촬영 → 제출을 진행한다. 이때도 `capture:progress`·`capture:done`을 보내므로 의사 화면이 열려 있으면 사진이 표시된다. 의사 화면은 진행 중인 요청이 없을 때 받은 촬영 이벤트에 한해 그 `batchId`로 바꾼다(의사 요청 없이 회차가 생기기 때문). 진행 중인 요청이 있으면 다른 `batchId`는 무시한다.

## 8. 지켜야 할 조건
- 서버 전용 키(Supabase service role, Anthropic API 키)는 서버 코드와 환경변수에만 둔다. 브라우저에는 공개 키만 둔다.
- 사진 버킷은 비공개이고, 사진은 서버가 발급한 임시 주소로만 보여 준다.
- 얼굴 분석은 환자 브라우저에서만 하고, wasm·모델 파일은 앱 안에서 제공한다.
- 화상통화 영상과 통역 문장은 어디에도 저장하지 않는다.
- 저장 사진은 반전하지 않은 원본이고, `left`/`right`는 환자 본인 기준이다.
- 제출된 촬영 회차는 항상 `front`·`left`·`right` 3장을 모두 가진다. 3장이 안 된 회차는 저장되지 않는다.
- 동의 없이 촬영을 시작하지 않는다.
- 환자에게 보이는 소견 번역은 항상 현재 원문을 번역한 것이다(`notes_ja_source = notes`일 때만 표시).
- 같은 역할은 한 번에 한 창만 통화에 참여한다.

## 9. 실행 환경
- video 앱은 `apps/video`에서 3001 포트로 띄운다. 노트북 2대에서 카메라를 쓰려면 HTTPS가 필요하다. 개발 서버를 HTTPS와 외부 접속 허용으로 띄우고(`next dev --experimental-https -H 0.0.0.0 -p 3001`에 해당), 다른 노트북은 `https://{IP}:3001`로 들어온다. LAN IP 접속 때 개발 리소스가 막히지 않도록 허용할 접속 주소를 환경변수로 받아 Next.js 설정에 넣는다. 소견 번역 기능에 CORS로 허용할 플랫폼 출처도 환경변수로 받는다. 플랫폼의 `NEXT_PUBLIC_VIDEO_BASE_URL`도 이 주소로 맞춘다.
- 네트워크는 같은 와이파이를 기본으로 쓴다. 기기 간 직접 연결이 막히면 중계 서버(설정했으면 자동), 휴대폰 핫스팟, 그것도 안 되면 Vercel 배포본 순으로 대비한다.
- Chrome 데스크톱만 지원한다. Web Speech API 인식은 음성을 Google 서버로 보내 처리하므로 인터넷이 필요하다. 시드 데이터는 가상 인물이라 데모에는 문제없지만, 실제 서비스에서는 의료 음성 데이터 처리 검토가 필요하다.
- **양쪽 모두 이어폰을 쓴다.** 같은 공간에서 소리가 되울리고, 상대 원음·번역 음성이 내 마이크로 들어가면 통역 인식이 섞인다.
- 시연에는 팀원 얼굴만 쓰고, 해커톤이 끝나면 사진 행과 버킷 파일을 직접 지운다(행 삭제만으로 파일은 지워지지 않는다).
- 환경변수(`apps/video/.env.local`): `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `ANTHROPIC_API_KEY`(서버 전용), 허용 개발 접속 주소, 허용 플랫폼 출처, 중계 서버 `TURN_URLS`·`TURN_USERNAME`·`TURN_CREDENTIAL`(선택 — 클라우드 중계 서비스 계정은 사용자가 준비). 플랫폼과 같은 Supabase 프로젝트를 쓴다. 키 이름만 `.env.example`에 둔다.

## 11. 검증과 시연 점검표
- 빌드·타입 검사·린트·자동 검사가 모두 오류 없이 끝나야 한다.
- 자동 검사는 Supabase·Claude API 없이 돌아야 한다. 그래서 촬영 판단 로직은 순수 로직으로, 번역 호출은 바꿔 끼울 수 있게 분리한다.
  - 촬영 판단: 단계별 경계값(정면 ±5°, 측면 35°·55° 안팎)과 상하 허용 범위, 좌우 부호(환자 기준 왼쪽이 좌측 단계로 판정), 막는 조건(얼굴 없음·2명 이상·크기·위치)이 막고 어두움은 막지 않음, 1초 유지 시 촬영·중간 이탈 시 타이머 초기화, 15초 뒤 수동 촬영 가능
  - 문구 파일: ja/ko 한쪽에만 있는 항목이 없음
  - 통역 번역 경로: 가짜 번역기로 성공 → 번역문, 실패·시간 초과 → 원문 + 실패 표시
  - 소견 번역: 가짜 번역기로 성공 → `done` + 번역한 원문 저장, 실패·거절 → `failed`, 번역 중 원문이 바뀌면 결과 버림, 빈 소견 → 409
  - 환자 화면 언어: 진료방마다 따로 기억, 새 진료방은 `lang`으로 시작
- 동작 확인은 아래 점검표로 사람이 노트북 2대에서 한다(사람 확인이 최종 근거).
- [ ] 다른 노트북에서 `https://{IP}:3001` 접속(Chrome), 카메라·마이크 허용
- [ ] 의원 콘솔·환자 화면에서 입장 → 1:1 영상·음성 연결
- [ ] 의사 한국어 → 환자 화면 일본어 자막 + 일본어 음성, 원문 함께 표시
- [ ] 환자 일본어 → 의사 화면 한국어 자막 + 한국어 음성
- [ ] 번역 음성이 나오는 동안 원음이 작아지고, 번역이 되돌아가지 않음
- [ ] [음성] 끄면 자막만 표시
- [ ] 숫자·횟수가 들어간 문장(예: "레이저 토닝 5회, 2주 간격") 번역 확인
- [ ] 환자 화면 일본어 → 한국어 → 일본어 전환, 새로고침해도 유지
- [ ] [얼굴 촬영 요청] → 환자 화면 배치 전환 + 동의 체크 → 일본어 정면 안내
- [ ] 정면·좌·우 자동 촬영, **저장된 좌측 사진이 실제로 환자의 왼쪽 얼굴**인지 확인
- [ ] 촬영마다 셔터 효과 + 의사 화면 진행 수 증가
- [ ] 미리보기에서 1장 [撮り直す] → 그 방향만 재촬영 → [提出する] → 의사 화면에 3장 표시
- [ ] 인터넷을 끊고 제출 → 사진 유지, [もう一度提出] 후 기록이 1개만 생김
- [ ] 촬영 도중 재요청 → 처음부터, 이전 사진 섞이지 않음
- [ ] 의사 [촬영 취소] → 환자 화면 통화 배치로 복귀
- [ ] 의사 탭을 하나 더 열기 → 먼저 연 탭이 멈추고 새 탭으로 연결
- [ ] 의사 [통화 종료] → 의사·환자 모두 각자 `returnUrl`로 이동, 의원 콘솔에서 통화 중 사진 확인
- [ ] 의원 콘솔에서 소견 저장 → 환자 견적 화면에 일본어 번역 + 「自動翻訳」, 소견 수정 직후 예전 번역이 보이지 않음 (플랫폼 요청 반영 후)
- [ ] 15초 미인식 → [手動で撮影] 동작
- [ ] 번역 키를 빼면 원문 + "번역하지 못했습니다"로 표시되고 통화는 계속됨
- [ ] `?test=1` 단독 촬영 동작
- [ ] 일본어 문구는 가능하면 일본어를 아는 사람이 한 번 읽어 봄
