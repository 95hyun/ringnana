# 화상 진료 중 얼굴 3방향 가이드 촬영 (face-capture)

> 소유: **화상통화 담당(`apps/video`)**. 플랫폼과 맞닿는 부분은 [video-integration.md](video-integration.md) §4 계약을 따른다.
> 상태: 초안 (2026-10-24). 플랫폼 쪽 확인이 필요한 항목은 [requests.md](requests.md)에 남겼다.

## 1. 무엇을 왜
- 화상 진료 중 의사가 [얼굴 촬영 요청]을 누르면, 환자 화면에 안내(문구 + 화살표 + 각도 진행바)가 뜬다. 환자가 안내대로 정면 → 좌측 → 우측으로 얼굴을 돌리면 **자동 촬영**되고, 사진은 의사 화면에 바로 도착한다.
- 화상통화 영상은 압축돼 색소 판독에 화질이 부족할 수 있다([product/plan.md](product/plan.md) §6 사진 표준화). 그래서 대화는 통화로 하고, **진단용 사진은 환자 단말 카메라 원본 화질로 따로 찍는다.** 통화는 끊지 않는다.
- 진료 전 `/photos` 사진(H2)은 그대로 둔다. 이 기능은 **통화 중 추가 촬영**이다. 의사가 사전 사진만으로 부족하다고 판단할 때 쓴다.
- 의료 판단은 하지 않는다. 자동 로직은 얼굴 검출·고개 각도·사진 품질 판단까지만 한다. 소견·견적은 의원 콘솔(H3)에서 의사가 작성한다.

## 2. 범위

| 포함 (데모) | 하지 않음 |
|---|---|
| 의사·환자 **1:1** 화상통화 (`role=interpreter`는 계약에만 두고 데모 미지원) | 3자 통화, 화면 공유, 통화 녹화 |
| 촬영 요청 → 가이드 촬영 → 의사 화면 실시간 표시 | 환자 미리보기·제출 단계 (바로 전송, 재촬영은 의사 재요청) |
| 사진을 플랫폼 `photos`에 저장 (의원 콘솔에서 열람) | 소견·견적 작성/표시 (플랫폼 담당) |
| 통화 종료 → `returnUrl` 이동 | TURN 서버, 카메라 선택, 모바일 대응 |

시간이 남으면 넣는 것: 밝기·흔들림 피드백, 일본어 음성 안내, 셔터음.

## 3. 데모 흐름 (노트북 2대)
1. 의원 콘솔·환자 화면에서 화상 진료에 입장한다. 진입 주소는 [video-integration.md](video-integration.md) §1의 `/room/{sessionId}?role=...`이고, 새 탭으로 연다.
2. 1:1 통화가 연결되고, 간단히 문진 대화를 한다.
3. 의사가 [얼굴 촬영 요청]을 누른다. 환자 화면은 **내 영상(가이드 포함)을 크게, 의사 영상을 작게** 바꾼다.
4. 환자가 안내대로 정면·좌측·우측을 돌리면 자동 촬영된다. 사진은 한 장씩 업로드되고, 의사 화면에 바로 표시된다.
5. 3장이 끝나면 환자 화면은 원래 배치로 돌아가고 "医師が写真を確認しています"를 표시한다.
6. 사진이 마음에 들지 않으면 의사가 다시 요청한다. 새 촬영 회차로 정면부터 다시 찍는다.
7. 통화가 끝나면 각자 `returnUrl`로 돌아간다. 의원 콘솔에서 통화 중 사진을 보며 소견·견적을 쓴다(H3).

## 4. 화면 규칙

### 4.1 공통
- 카메라·마이크는 한 번만 요청한다(1920×1080 우선, 안 되면 1280×720). 같은 영상을 통화와 촬영에 쓴다.
- 내 영상은 거울처럼 좌우 반전해서 보여 준다. **저장 사진은 반전하지 않은 원본**이다.
- 언어: 환자 화면은 일본어, 의사 화면은 한국어(`lang` 파라미터 기준).
- 상대 입장 표시: 의사 "환자 대기 중 / 환자 연결됨", 환자 "医師をお待ちください / 医師と接続しました".
- 의사가 연결을 제안하고 환자가 응답한다(역할 고정). 새로고침·재입장 때는 의사가 다시 제안해 재연결한다. 상대가 나가면 연결을 정리하고 대기 상태로 돌아간다.

### 4.2 의사 화면
- [얼굴 촬영 요청]은 환자가 방에 있을 때만 누를 수 있다.
- 요청하면 **새 촬영 회차(batch)**가 생긴다. 이전 회차 사진은 화면에서 내리고 "촬영 중 0/3"을 표시한다. 정면·좌측·우측 자리에 사진이 도착하는 대로 채운다.
- 촬영 도중 다시 요청해도 새 회차로 정면부터 시작한다.

### 4.3 가이드 촬영 (환자 브라우저에서만 분석)
- 얼굴 검출과 고개 각도 추정은 MediaPipe Face Landmarker(`@mediapipe/tasks-vision`)로 한다. wasm과 모델 파일은 앱 안에 두고, CDN은 쓰지 않는다. 얼굴 특징값은 저장하지도 전송하지도 않는다(신원 확인 아님).
- 순서는 정면 → 좌측 → 우측으로 고정한다. **좌우는 환자 본인 기준**이고, 화살표는 거울 모드 화면에서 고개를 돌리는 방향과 맞춘다.

| 단계 | 안내 (환자, 일본어) | 촬영 조건 (기본값, 조정 가능) |
|---|---|---|
| 정면 `front` | 正面を向いてください | \|yaw\| ≤ 5°, \|pitch\| ≤ 15° |
| 좌측 `left` | 顔を左に向けてください ◀ | 본인 왼쪽으로 yaw 35°~55° |
| 우측 `right` | 顔を右に向けてください ▶ | 본인 오른쪽으로 yaw 35°~55° |

| 상태 | 표시 (환자, 일본어) |
|---|---|
| 얼굴 없음 | 顔を枠の中に合わせてください (가이드 회색) |
| 2명 이상 | お一人だけ映るようにしてください |
| 너무 멂 / 가까움 | もう少し近づいてください / 少し離れてください |
| 각도 초과 | 少しだけ戻してください |
| 조건 충족 | 가이드 초록색. 약 1초 유지하면 촬영하고, 벗어나면 다시 센다 |
| 촬영 완료 | ✔ 표시 후 다음 단계 |

- 한 단계에서 15초 동안 자동 촬영이 안 되면 [手動で撮影] 버튼을 띄운다. 이렇게 찍으면 `capture_mode = manual`이다.
- 사진은 카메라 원본 해상도 프레임을 JPEG(품질 약 0.92)로 만든다.
- 업로드에 실패하면 그 단계에 머물며 [再送信]으로 같은 사진을 다시 보낸다.
- 각도·시간 기준값은 설정 파일 하나에 모아 현장에서 조정할 수 있게 한다.

### 4.4 새로고침
- 의사 화면은 처음 열릴 때 그 진료의 최신 촬영 회차 사진을 다시 불러온다.
- 환자가 촬영 도중 새로고침하면 그 회차는 이어 찍지 않는다. 의사가 다시 요청한다.

## 5. video 앱 내부 구조 (플랫폼과 무관)
- 연결 정보 교환과 화면 간 알림에는 Supabase Realtime(Broadcast + Presence)을 쓴다. 채널은 진료당 하나이고, 이름 `video:{sessionId}`로 플랫폼 채널과 겹치지 않게 한다. STUN은 공개 STUN만 쓴다.
- 이벤트 이름은 `signal`(offer/answer/ice), `capture:request {batchId}`, `capture:progress {batchId, angle}`, `capture:done {batchId}`이다. 각 화면은 현재 회차와 다른 `batchId`의 이벤트를 무시한다(재요청 뒤 늦게 도착한 이전 사진이 섞이지 않게).
- 사진 업로드·조회는 video 앱 서버 경로에서만 한다. 서버 전용 키는 서버에만 둔다. 브라우저에는 사진 임시 주소(signed URL, 10분)만 준다.
- 개발·비상용 진입: `?role=patient&test=1`이면 통화 없이 촬영 → 업로드만 단독으로 실행한다.

## 6. 플랫폼에 저장하는 방식 → [video-integration.md](video-integration.md) §4
- 저장 위치는 플랫폼과 같은 Supabase의 `photos` 테이블과 비공개 사진 버킷이다.
- 진료는 `consultations.video_session_id = sessionId`로 찾는다.
- 필요한 컬럼 추가와 버킷 이름은 H1에 요청했다([requests.md](requests.md)).

## 7. 실행 환경
- video 앱은 `apps/video`에서 3001 포트로 띄운다. 노트북 2대에서 카메라를 쓰려면 HTTPS가 필요하다. 개발 서버를 HTTPS와 외부 접속 허용으로 띄우고(`next dev --experimental-https -H 0.0.0.0 -p 3001`에 해당), 다른 노트북은 `https://{IP}:3001`로 들어온다. 플랫폼의 `NEXT_PUBLIC_VIDEO_BASE_URL`도 이 주소로 맞춘다.
- 네트워크는 같은 와이파이를 기본으로 쓴다. 기기 간 통신이 막히면 휴대폰 핫스팟, 그것도 안 되면 Vercel 배포본을 쓴다.
- 같은 공간에서 소리가 되울리지 않도록 의사 쪽은 이어폰을 쓴다.
- 환경변수(`apps/video/.env.local`): `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`. 플랫폼과 같은 Supabase 프로젝트를 쓴다.

## 8. 시연 점검표
- [ ] 다른 노트북에서 `https://{IP}:3001` 접속, 카메라·마이크 허용
- [ ] 의원 콘솔·환자 화면에서 입장 → 1:1 영상·음성 연결
- [ ] [얼굴 촬영 요청] → 환자 화면 배치 전환 + 일본어 정면 안내
- [ ] 정면·좌·우 자동 촬영, 좌우가 환자 본인 기준과 일치
- [ ] 의사 화면에 사진이 한 장씩 도착
- [ ] 촬영 도중 재요청 → 처음부터, 이전 사진 섞이지 않음
- [ ] 통화 종료 → `returnUrl` 이동, 의원 콘솔에서 통화 중 사진 확인
- [ ] 15초 미인식 → [手動で撮影] 동작
- [ ] `?test=1` 단독 촬영 동작

## 9. 이후 (구현하지 않음)

- 경과 비교: 사후관리 체크인 사진과 같은 각도로 나란히 보기. 그래서 각도 값(yaw/pitch)을 함께 저장해 둔다.
