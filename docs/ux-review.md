# UI/UX QA — 글로벌 비즈니스 플랫폼 기준 (2026-10-24)

> 방법: `my` 브랜치(41809ed + 미커밋 i18n 마무리)를 로컬 dev 서버에 띄우고, Chrome(playwright-core)으로 jp·ko × 모바일 390px(환자)·데스크톱 1440px(의원)에서 캡처해 확인했다. 시드 계정 `misaki@ringnana.demo`로 로그인.
> 2차(쓰기 흐름, 사용자 허가): 새 환자 가입 → 문진 → 셀카 → 의원 견적 작성·확정 → 환자 예약 → 기존 환자 체크인 제출 → 의원 검토까지 실행했다. 미검증: 화상 입장(video 앱 필요).
> 담당 = 현재 레인 소유 기준. 우선순위(P0~P2)는 2026-10-24 사용자 확정. 순서: P0 → P1 → P2(여유 시).

## 잘 된 점
- 랜딩 가치 제안이 명확하다("診察も見積もりも、日本にいるうちに。"), 5단계 여정이 한눈에 보인다.
- 문진의 금기 스크리닝이 구체적이고, 의원 큐에 금기 플래그(抗凝固薬)가 빨간 배지로 바로 보인다.
- 견적이 "확정 금액, 내원 시 변경 없음"을 명시한다 — 핵심 차별점(가격 투명성)이 화면에 살아 있다.
- 의원 진료 상세에 문진·사진·소견·견적이 한 화면에 있고, 시술 프리셋 버튼으로 견적이 빠르다.

- 견적 경로 `/[lang]/quote/[id]`의 `id`는 **진료(consultation) ID**다(견적 ID 아님). 코디네이터가 사용자에게 알려준 견적 URL이 틀렸었다 — 문서에 명시 권장(architecture.md 라우트 표).
- Next.js dev 서버를 경로 이동 전부터 켜 두면 사전 키 누락 500이 났다가 재시작하면 사라진다(실측). 큰 이동 뒤에는 dev 서버 재시작.
